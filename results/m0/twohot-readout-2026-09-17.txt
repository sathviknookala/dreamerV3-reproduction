# symexp_twohot readout: transform-of-expectation vs expectation-of-transform

bins=255  support=+/-symexp(20)=+/-4.851652e+08
v1 bin spacing: uniform in symlog space, b in [-20.0,20.0]
v2 bin spacing: symexp-spaced in value space, b in [-4.851652e+08,4.851652e+08]
v2 neighbours around zero: -0.170558, 0.000000, 0.170558

## 1. Each encoding is exact for its OWN two-hot target

           y    v1 symexp(E[b])            v2 E[b]
           0                  0                  0
           1                  1                  1
        -3.5               -3.5               -3.5
         100                100                100
       1e+04              10000              10000

Two-hot is linear interpolation, so each recovers its target exactly. No bias here.

## 2. They diverge on SPREAD distributions - what a trained critic actually emits

Bimodal return: mass q on value `hi`, mass (1-q) on 0. True mean = q*hi.

        hi      q    true mean     v1 readout     v2 readout       v1 err
       100   0.50           50        9.04988             50     -40.9501
       100   0.10           10       0.586471             10     -9.41353
      1000   0.50          500        30.6386            500     -469.361
        10   0.50            5        2.31662              5     -2.68338
         1   0.50          0.5       0.414214            0.5   -0.0857864

symexp is convex on the positive half, so symexp(E[b]) <= E[symexp(b)] (Jensen).
v1 reads out a symlog-space average, biased toward zero for spread mass.
v2 reads out the mean of its own predicted distribution over values.

## 3. Accumulation order matters in float32 - by cancellation, not magnitude

The bins are symmetric, so a symmetric p must read out exactly 0. Zero-init of the
twohot output weights is what makes predictions start at 0; naive accumulation can
break that guarantee. Cases below all have true readout 0.

case                   fsum f64       seq f32     np.sum f32   halves f32   mirror f32
uniform 1/255                 0          0.25             -1            0            0
spike + tail 1e-04            0   -0.03515625              0            0            0
spike + tail 1e-06            0             0 -0.00024414062            0            0

Extreme bin magnitude is 4.852e+08. Terms of that size cancel between the
symmetric tails; in float32 an O(1e8) partial sum has an ulp near 32, so anything
O(1) added between the two tail terms is absorbed and the cancellation leaves a
residue instead of 0. The residue is an ABSOLUTE error floor, not a relative one,
so it matters most where the true value is near zero - i.e. at initialisation.

Note which reductions fail: sequential and pairwise (np.sum) break on DIFFERENT
cases above. A framework's default reduction is not a safeguard.

`halves` sums each signed half from small |b| to large. `mirror` is the
reference algorithm (outs.py TwoHot.pred at the pinned commit): reverse the
negative-half products onto the positive-half products and add ELEMENTWISE, so
each mirror pair cancels in one operation, then sum. Implement `mirror` - it is
exact by construction for symmetric p rather than exact by luck of ordering,
and it is what the reference does.

## 4. What this does NOT establish

v2 removes the transform-order bias in reading the mean of the PREDICTED
distribution. It does not make the value estimate an unbiased estimator of true
environment return. Independently of readout order:
  - the predicted distribution is a learned approximation of unknown accuracy;
  - lambda-returns bootstrap off the critic, so targets carry the critic's own error;
  - the two-hot target is a projection onto a finite support, and |y| > symexp(20)
    saturates at the end bins;
  - the slow-critic regulariser biases toward an older parameter set by construction.
Unbiasedness w.r.t. environment return is not claimed and is not measurable here.
